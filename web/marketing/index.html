knievel

Fearlessly fast ad delivery that steals the show.

A self-hosted, multi-tenant direct ad server for publishers. Rust handlers, PostgreSQL tenancy, a generated OpenAPI contract, a browser admin app, Compose, and Helm — without an exchange or a second datastore.

What Knievel is

  • Direct serving. Advertiser → campaign → flight → ad and site/zone inventory, openly inspired by Kevel's domain model.
  • Self-hosted tenancy. Project requests are bound through PostgreSQL FORCE ROW LEVEL SECURITY under a non-superuser app role.
  • One generated contract. The Rust service emits OpenAPI 3.0; the human table is checked as exact method/path pairs for all 62 generated operations.
  • Not OpenRTB. No bid request flow, SSP, auction, GraphQL API, Redis, or Kafka.

Current architecture

┌──────────────┐     bearer + project path      ┌──────────────┐
│ Calling app  │ ─────────────────────────────▶ │   knievel    │
│ or admin SPA │ ◀───────────────────────────── │ (Rust/poem)  │
└──────────────┘                                └──────┬───────┘
                                                          │ RAM snapshot
                                                          ▼
                                                   ┌──────────────┐
 GET /e/i/<signed> ── best-effort event channel ─▶ │  PostgreSQL  │
 GET /e/c/<signed>          per-row INSERTs        │ config/events│
                                                   └──────────────┘

Each pod cold-loads configuration and polls a sequence every five seconds. Management writes do not currently bump that sequence and LISTEN/NOTIFY is not active, so write-triggered refresh is not a shipped guarantee. Event batches use per-row INSERTs, not COPY. Retention is detach-not-drop, and the broad 2026 seed leaf currently overlaps the daily maintenance ranges. Read the verified flow in ARCHITECTURE.md.

What ships

Decision API

Multi-placement selection, blocklists, priority tiers, weighted choice, typed creative responses, Liquid rendering, and an explainer. Authentication and tenant proof still touch PostgreSQL before the selection core reads RAM.

Management API

Generated org/project, token, ad-library, demand, inventory, creative-template, image-upload, and taxonomy operations. The exact operation set is the contract; older member/project-update designs are not routes.

Events & rollup

Decision, impression, and click rows flow through a bounded memory channel into partitioned PostgreSQL. events_rollup is computed hourly. Timestamp-sensitive dedup and detached retention leaves require operator care.

Opaque + JWT auth

Argon2-backed opaque tokens are always available with a database. Configured issuer policies add JWT verification; RS256 is the usable runtime key path today. There is no auth.modes disable switch.

Browser admin

The release image serves a React app at /admin/. OIDC PKCE and pasted opaque tokens both use browser sessionStorage, so same-origin XSS is a bearer-token boundary.

Deployment artifacts

Native amd64/arm64 image manifests, an OCI Helm chart, a reference Compose stack, and three CLI archive targets are produced only from an explicit release tag.

Know the limits

  • Creative image uploads use process-local memory and disappear on restart; no S3/MinIO backend is wired.
  • OTel and Sentry config is parsed/stubbed, but no exporter or SDK sends data.
  • There is no /metrics route; the chart ServiceMonitor option is unsupported.
  • api.public_base_url is parsed but tracking URLs are currently relative /e/... paths.
  • /readyz checks DB reachability only, not snapshot or event-flusher health.
  • DB-backed tests can self-skip without DATABASE_URL; most acceptance and all chaos designs are not active coverage.

Quickstart

Create the writable token directory, start only PostgreSQL and the server, wait for health, then run the DB-direct seeder as your host UID/GID: 

git clone https://github.com/knievel-ads/knievel
cd knievel
mkdir -p tmp

docker compose -f examples/compose/compose.yaml up -d \
  knievel-postgres knievel
until curl -fsS http://localhost:8080/healthz; do sleep 2; done

docker compose -f examples/compose/compose.yaml run --rm \
  --user "$(id -u):$(id -g)" knievel-seed

Capture the printed project/site/ad-type IDs, restart Knievel for a cold snapshot load, and issue the real decision curl from the verified README sequence. The IDs are not assumed to be 1.

Deploy deliberately

  • Image: ghcr.io/knievel-ads/knievel; use @sha256:... in controlled environments.
  • Helm: oci://ghcr.io/knievel-ads/charts/knievel; supply DB coordinates, Secret, and api.publicBaseUrl.
  • Database: the reference and CI environment use PostgreSQL 16 with a NOSUPERUSER NOBYPASSRLS app role and a separate NOLOGIN BYPASSRLS loader role.
  • Local image: cargo xtask build-image --tag knievel:local; the Dockerfile packages prebuilt artifacts.
